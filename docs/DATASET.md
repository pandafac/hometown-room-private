## 定位

云溪镇是一座专为本产品演示创建的虚构江南水乡小镇。所有地名、店铺、店主、菜单、评论与体验回声均非真实信息；界面页脚提供全局虚构声明。

每家店包含：店铺故事、产品与价格、营业时间、今日状态、单人座位、点单方式、本地礼仪、常见误解、店主愿意回答的问题、不能回答的问题、宠物政策、无障碍信息、支付方式、FAQ、店主推荐和体验回声。

`liveStatus` 是访问端状态标签的数据源，包含：

- `business`：营业中、今日已收门等营业状态。
- `crowd`：余位较少、满座、无需排队等客流状态，可为空。
- `stock`：部分商品售罄或今日售罄。
- `updatedAt`：店主更新状态的展示时间。

状态是虚构 Demo 数据，不构成实时营业、库存或排队承诺。

每家店另外维护 30–36 条结构化店主知识，总计 170 条，覆盖位置、营业高峰、菜单、独行座位、设施、摄影、支付、天气、亲子、无障碍、忌口、联系边界和安全边界。

- `owner-knowledge.json`：原始核心资料。
- `owner-knowledge-extra.json`：新增的忌口、食材、办公、天气、亲子、联系边界等扩展资料。

## 数据边界

- `faqs` 与店铺字段是 AI 可以引用的事实来源。
- `testimonials` 只用于说明其他人的体验，不能推导价格、营业或承诺。
- 预置体验回声全部标记 `simulated: true`。
- 商家新提交的体验回声标记为真实提交。开发服务的进程重启后恢复种子；单文件版使用浏览器 `localStorage` 持久化。
- 店主补充的新 FAQ 会立即进入下一轮 AI 上下文。
- 未提供字段必须以“店主资料里还没有写”回答，并上报资料缺口。

## 动态闭环

```text
游客问题
  -> AI 判断 full / partial / missing
  -> 问题进入商家回声板
  -> 店主补充缺失资料
  -> 新 FAQ 写入当前会话运行时
  -> 下一次相同问题得到完整回答
```

## 重要体验回声规则

1. 预置内容不可声称是真实用户反馈。
2. 真实反馈需要用户同意匿名展示，不采集联系方式。
3. 反馈只作为体验证据，不参与事实判断。
4. 内容工坊不使用个人原话做广告，只使用问题主题与店主授权事实。
